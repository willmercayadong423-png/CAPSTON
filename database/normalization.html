Problems: repeating groups · non-atomic cells · massive duplication · update anomaly (fix an email on 10 pages) · insert anomaly (new student with no requests has no page section) · delete anomaly (remove the last request → the student disappears).
▼ make every cell atomic · flatten the repeating group · pick a primary key → First Normal Form

Stage 3 — 2NF · Second Normal Form no partial dependencies

Key the 1NF table by the natural composite key ( StudentID + RequestNo ), then test every attribute against it:

Stage 4 — 3NF · Third Normal Form no transitive dependencies

Chain 1 — the role name. Stored as free text on every student row:

StudentID──▶ RoleName──▶ (should constrain) "Student | Registrar | Admin" ✗ transitive + typo risk (“Studnet”)
FIX ▶ StudentID──▶RoleID ──▶ROLES (RoleID PK, RoleName) ✓ lookup table

Final Result — the normalized schema = the live database

Solid arrows = enforced foreign keys (6). Dashed = intentional soft reference. This is exactly what database/erd.html generates from the live hehms database.

Result: 3 relationships → 6 enforced FKs, zero orphan tables, every table in 1NF · 2NF · 3NF. Deliberate exceptions (audit snapshots, request-time snapshots, soft email ref) are documented design decisions, not oversights.

Beyond 3NF — the decisions panelists ask about

  • 1:1 student_profiles split — LRN/Grade/SY apply only to students; staff rows carry no NULL academic columns.
  • Audit & request snapshots kept denormalized — an append-only trail must show values as they were at event/request time, surviving renames and deletions.
  • credential_resend_log soft reference — disposable abuse-protection data; not business data.
